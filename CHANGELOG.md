# Changelog

## v3.2 — исправлено ожидание полного обхода больших запросов

- Быстрый ответ из просмотренной части, постепенное чтение всех доступных страниц без общего потолка.
- Индекс/курсор в search_cache переживают рестарт и не истекают для частичного обхода.
- До 6 страниц на вызов, 20 сек по умолчанию; старые большие настройки ограничены 30 сек.
- count — подсказка; пустая страница с положительным count больше не повреждённый ответ.
- Новые найденные посты доступны при сбое следующих страниц, без возврата показанного.
- Диагностические логи страницы и причины остановки; 55 регрессионных теста.
- Не гарантируем глобально лучший арт среди ещё не прочитанных сотен тысяч.


## v3.1 — полный поиск и строгий анти-повтор

- Вся доступная API выдача вместо 6 страниц; count или обход до пустой страницы.
- Дисковый индекс и ленивое ранжирование; долгий обход возобновляется при повторном запросе.
- SQLite-история без лимитов 500/500, общая для одного Discord-канала независимо от тегов.
- Атомарные резервы перед отправкой, проверка MD5/SHA256 фактических файлов.
- Удалён автоматический возврат уже показанного; сбои API не подменяются повторами.
- Неопределённые доставки сохраняют резерв после рестарта; известные отказы освобождают его.
- Временный пропуск недоступных файлов, стабильная идентичность Telegram-поста по peer.
- Однократный консервативный импорт старого JSON; 42 новых регрессионный тест.
- Это локально проверенная версия; live-проверка API и доставки на хостинге ещё нужна.

## v3.0 — переписан движок: быстрее, честнее выбор, готов к хостингу 🛠️

Код разнесён по модулям: `content_filter.py` (все блэклисты и правила),
`booru.py` (сайты и поиск), `selection.py` (анти-повтор), `bot_gelbooru.py`
(команды). Контент-политика (блэклисты, HARD-блок, нагота, приколы) не менялась.

### 🎯 Выбор арта
- **Раздетое теперь реально первым.** Раньше одетый арт с большим score мог
  обогнать раздетый — «чемпион» выбирался по score из всего пула. Теперь порядок:
  свежее раздетое → свежее одетое (запасной вариант) → давно показанное.
- **Умное листание вместо 6–12 запросов на каждый поиск.** Берётся топ-100 по
  лайкам; глубже бот лезет, только если свежих лучших артов мало (или по
  запросу части тела не хватает артов с нужным фокусом). Страницы кэшируются на
  10 минут. Популярный тег — обычно 1 запрос к API вместо 6+.
- Запрос с `nude` добирается, только когда мало именно *непоказанного*
  раздетого, и не дёргается для несуществующих тегов.
- Двое одновременно с одним тегом больше не получают один и тот же арт.

### 🐞 Исправлено
- **`/safebooru` в обычных каналах мог показать questionable** — на Safebooru их
  ~17 тысяч. Теперь режутся и на сервере, и локально по рейтингу.
- **Kanzaki Hideri на хостинге не работал** — картинка бралась по пути
  `C:\Users\...`. Теперь она в репо: `assets/kanzaki_hideri.jpg`.
- **Заблокированный тег (например `collar`)** уходил в запрос вместе с
  `-collar` и молча давал «ничего не найдено». Теперь честное «🚫 заблокирован».
- Сообщения о блокировке видит только автор (раньше — весь канал) и они не
  тратят кулдаун. Тег с минусом (`-tag`) исключает его и не триггерит блок.
- Ошибки различаются: «сайт не отвечает / нужен API-ключ / лимит запросов» —
  вместо «ничего не найдено» или «файлы слишком большие» на любой сбой.
- Скачанный файл проверяется: хотлинк-заглушка Gelbooru (HTML вместо картинки)
  больше не может уйти в Discord битым файлом. Скачивание — один запрос со
  стримингом и лимитом размера (раньше HEAD + GET).
- Konachan: локальный фильтр рейтинга, сортировка по score больше не теряется
  при 4 тегах; для больших PNG берётся `jpeg_url` до сжатого sample.
- Серверы с бустом 2+ уровня получают лимит 50/100 МБ вместо 10.
- `on_ready` больше не пересинхронизирует команды и не сносит их при каждом
  переподключении к Discord (риск рейт-лимита) — только один раз.
- Память показанного пишется на диск раз в 30 с и при выключении, а не
  синхронно на каждый показ (файл в мегабайты тормозил бота).
- `/tg`: реклама в альбоме ловится по всему альбому (подпись висит только на
  одной картинке — остальные проскакивали); скан канала кэшируется на 10 минут.
- `/tags`: один запрос вместо 20, теги с числом артов; убраны мёртвые/устаревшие
  (`blonde`, `outdoor`, `kemonomimi`…) и бесполезные из-за HARD-блока (`1boy`).
- `/tagcheck`: настоящее число артов и подсказка похожих тегов при опечатке.
- Регистр тегов не важен (`Hatsune Miku` = `hatsune_miku`).
- Пароль прокси больше не пишется в лог.

### 🔒 Безопасность

## v2.5 — запрошенная часть тела теперь в фокусе 🎯

Ищешь `breasts` — получаешь арт, где грудь и есть сюжет, а не фоновый тег при
жопе/письке. Как при поиске прямо на сайте.

- **Причина.** Бот проверял лишь *наличие* тега, а `breasts` висит на огромной
  доле NSFW-арта. По `sort:score` наверх всплывал самый залайканный explicit —
  обычно с фокусом на `ass`/`pussy`, где грудь почти не видно.
- **Фокус-ранжирование.** Для телесных запросов (breasts / ass / pussy / feet)
  бот распознаёт «сюжет» арта по emphasis-тегам (`large_breasts`, `cleavage`,
  `nipples`, `paizuri`…) и поднимает посты, где в фокусе **запрошенная** часть, а
  те, где сюжет — **другая** часть тела, опускает вниз. Мягкий приоритет с
  фолбэком: «не то» не выбрасывается, поэтому по нишевым тегам выдача не пустеет.
- **Нагота увязана с запросом.** Раньше арт проходил фильтр наготы за счёт любого
  `ass`/`pussy`/`cameltoe` — теперь для запроса `breasts` нужна общая нагота или
  нагота именно груди (голая жопа сама по себе тег `breasts` больше не вытягивает).
- Для персонажей/поз/серий поведение прежнее — приоритет включается только для
  телесных тегов. Качество (приоритет по лайкам) и анти-повтор не затронуты.

## v2.4 — кулдаун поиска 10с → 6с ⏱️

- Кулдаун поисковых команд (`/gelbooru`, `/safebooru`, Konachan) смягчён:
  было 3 запроса за 30с (~1 поиск в 10с), стало **5 за 30с (~1 поиск в 6с)** на

  сохранён.

## v2.3 — качество артов вернулось 🎨

Выдача снова присылает топовые арты, как раньше.

- **Причина просадки.** В погоне за разнообразием бот стал черпать арты с глубоких
  страниц по score — вплоть до ~2400-го по лайкам, — поэтому пул на ~90% состоял
  из посредственного. Качество просело.
- **Фикс — мягкая ротация.** Теперь подмешиваем только **неглубокие** страницы
  (1–10) с сильным уклоном к началу: страницы 1–5 берутся почти всегда, глубже —
  редко. Почти все кандидаты снова высокорейтинговые, но пул всё ещё ротируется
  (повторы не возвращаются).
- **Сильнее приоритет по лайкам.** Потолок веса при перемешивании поднят
  (12 → 25) — по-настоящему залайканные арты чаще оказываются вверху.

## v2.2 — Safebooru 🟢

- **Новая команда `/safebooru`.** Поиск по тегам на Safebooru — это safe-контент
  (без хентая), поэтому команда работает **в любом канале**, а не только в NSFW.
  До 4 тегов, выдача — самое залайканное по реакциям.
- **Та же система тегов.** Блокировки и «приколдес»-теги (как у `/gelbooru`)
  действуют и здесь, плюс общий анти-повтор из v2.1.

## v2.1 — меньше повторов 🔁

Бот стал заметно реже присылать одно и то же.

- **Память переживает рестарт.** Список уже показанных артов теперь сохраняется на
  диск (`recent_shown.json`) и подгружается при старте — раньше каждый
  перезапуск на хостинге обнулял память, и повторы возвращались с нуля.
- **Помним больше.** На каждый набор тегов держим в памяти последние 60 артов
  вместо 25 — популярные теги дольше не повторяются.
- **Шире выбор.** Среди качественных артов (по реакциям) выбор стал почти
  равномерным: один мега-популярный арт больше не вылезает в большинстве выдач.
  Приоритет лайкам сохраняется — мусор по-прежнему остаётся внизу.

## v2.0 — арты из Telegram и умный поиск 🚀

Большое обновление: бот научился доставать арты прямо из Telegram-каналов, а сам
поиск стал заметно умнее. Шанс наткнуться на рекламу или мусор теперь почти нулевой.

### 🆕 Новая команда `/tg`
- **Поиск артов в Telegram.** Бот тянет картинки и гифки из наших Telegram-каналов и
  присылает их прямо в Discord — больше не нужно никуда переходить.
- **Выбор канала.** `/tg` — случайный канал из списка, либо `/tg channel:<название>` —
  конкретный. С автоподсказкой названий прямо при вводе.

### ✨ Поиск стал умнее
- **Минимум мусора.** Реклама, посты с кнопками-ссылками и записи без картинок
  отсеиваются автоматически — шанс наткнуться на фигню почти нулевой.
- **Сначала лучшее.** Арты ранжируются по реакциям, так что наверх всплывает то, что
  реально зашло аудитории, — но с долей случайности, чтобы не было однообразия.
- **Без повторов.** Бот помнит, что уже показывал, и старается не присылать одно и то же.
- **Только в NSFW.** Команда работает исключительно в NSFW-каналах — как и положено. 🔞

### 🎬 Медиа
- Большие файлы обрабатываются аккуратно: если арт не влезает в лимит Discord, бот
  подберёт следующий подходящий, а не выдаст ошибку.

## v1.5 — исправления и полировка

### 🔒 Безопасность
- Токен бота и `GELBOORU_API_KEY`/`GELBOORU_USER_ID` больше **не зашиты в код** — читаются из
  переменных окружения (`DISCORD_BOT_TOKEN`, `GELBOORU_API_KEY`, `GELBOORU_USER_ID`).
- `bot.run(...)` убран из тела модуля и обёрнут в `if __name__ == "__main__"` — теперь файл
  можно импортировать (например, для тестов) без автоматического подключения к Discord.

### 🔍 Поиск и фильтры
- **Реальная случайность результатов.** Gelbooru игнорирует параметр `sort=random`; теперь
  используется тег `sort:random`. Раньше бот выдавал одни и те же (самые свежие) посты.
- **Фильтр больше не пропускает запрещённый контент.** Убран откат к нефильтрованному списку
  при наличии менее 5 «чистых» постов — отдаются только прошедшие блэклист.
- **Точное совпадение блокированных тегов.** Проверка по подстроке ошибочно блокировала
  легитимные теги (`futaba_sakura`, `strap`, `contrast` из-за `futa`/`trap`). Теперь сравнение
  по токенам тега.

### ⏱️ Кулдауны
- Кулдауны теперь действительно работают. Декоратор `@commands.cooldown` для слэш-команд
  nextcord молча игнорировался; реализован собственный sliding-window кулдаун
  (`/gelbooru` 3/30с, `/tagcheck` 5/30с, `/tags` 1/30с).

### 🎬 Медиа
- **Видео (mp4/webm)** теперь скачивается и отправляется файлом — Discord его проигрывает.
  Раньше отдавалась только ссылка. При превышении лимита — фолбэк на ссылку.
- Лимит размера файла берётся из реального лимита сервера (`guild.filesize_limit`) вместо
  жёстких 8 МБ; для личных сообщений — безопасные 10 МБ.
- Логика скачивания (HEAD-проверка размера + ретраи) вынесена в общий помощник `download_media`.

### 🛠️ Стабильность
- Исправлен жизненный цикл HTTP-сессии: `on_disconnect` больше не закрывает общую сессию при
  кратковременных разрывах, а `on_ready` не создаёт новую сессию при каждом реконнекте (утечка).
- Добавлен глобальный обработчик ошибок команд `on_application_command_error`.
- NSFW-проверка безопасна для веток/тредов и нестандартных каналов (`getattr` вместо прямого вызова).
- Устойчивый парсинг ответа: одиночный пост-словарь и формат `{"tag": [...]}` обрабатываются корректно.
- Единый сборщик параметров запроса `base_params()` (ключи API добавляются только если заданы).

### ✅ Тесты
- Добавлен `test_bot.py` — 29 юнит-тестов (parse_posts, post_is_clean, блок-теги, кулдаун, blacklist, base_params).

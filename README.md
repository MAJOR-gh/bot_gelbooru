# Gelbooru Discord Bot (v3.4)

Discord-бот на `nextcord`: ищет арты по тегам на booru-сайтах и в
Telegram-каналах и присылает картинки / GIF / видео. Показывает лучший по
лайкам арт, который в этом Discord-канале ещё не показывал. Ищет по **всей** выдаче
тега — в том числе глубже потолка пагинации Gelbooru (20 000 постов).

## Команды
- `/gelbooru <тег> [тег2] [тег3] [тег4]` — арт по 1–4 тегам с **Gelbooru**.
  Ищешь часть тела (breasts/ass/pussy/feet) — наверх идёт арт, где она и есть
  сюжет, а не фоновый тег. `-тег` исключает тег.
- `/konachan <тег> …` — то же с **Konachan** (аниме-арт).
- `/safebooru <тег> …` — **Safebooru**, только safe-контент; работает в любом канале.
- `/tg [канал]` — топовый по реакциям пост из **Telegram**-канала (реклама
  отсеивается), весь альбом целиком.
- `/tags` — популярные теги и сколько по ним артов.
- `/tagcheck <тег>` — есть ли тег на Gelbooru + похожие теги при опечатке.
- `/help` — справка.
- `/status` — приватная диагностика API, задержки Discord, кэша и последнего поиска в канале.

Под booru-артом — **Next**: продолжает тот же запрос без повторов. Кнопка доступна
автору в исходном канале, действует 10 минут и использует кулдаун исходной команды.
После рестарта старые кнопки не работают — повтори команду (дисковый курсор сохранён).
Все четыре поля тегов поддерживают автодополнение и подсказки опечаток.
В обычных каналах — только безопасные локальные подсказки; в NSFW-каналах —
также API Gelbooru/Safebooru, если доступно. Для Konachan — локальные варианты.
Подсказка не заменяет введённый тег автоматически и не гарантирует его наличие на сайте.

NSFW-команды (`/gelbooru`, `/konachan`, `/tg`, `/tagcheck`) работают только в
NSFW-каналах.

## Переменные окружения
Кладутся в файл `.env` рядом с ботом (шаблон — `.env.example`) или в
переменные окружения хостинга.

- `DISCORD_BOT_TOKEN` — токен бота (**обязательно**).
- `GELBOORU_API_KEY` / `GELBOORU_USER_ID` — **обязательно для /gelbooru**: без
  ключа Gelbooru отвечает 401. Берутся на gelbooru.com → My Account → Options.
- `DISCORD_GUILD_IDS` — ID серверов через запятую для **мгновенной** регистрации
  команд. Пусто → глобальная регистрация (до ~1 ч).
- `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING` — для `/tg`. Строку сессии
  выдаёт `python tools/tg_export_session.py`. Без них `/tg` отключена.
- Необязательно: `GELBOORU_PROXY` (если сайты заблокированы), `MAX_UPLOAD_MB`
  (потолок размера файла), `DATA_DIR` (куда писать память показанного),
  `PORT` (если хостинг его задаёт — поднимается health-эндпоинт `/health`),
  `SEARCH_TIMEOUT_SECONDS` (бюджет поиска на вызов, по умолчанию 20 секунд, рабочий потолок 30).

## Запуск локально
```bash
python -m venv venv
venv\Scripts\activate            # Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env           # и впиши токен/ключи
python bot_gelbooru.py
```

## Хостинг 24/7
Сейчас бот живёт на [Wispbyte](https://wispbyte.com/client) (бесплатно).
Обновление: push в `main` → **Restart** в панели — при старте сервер сам
скачивает свежий код и ставит зависимости. Подробно — в
[гайде, раздел 12](docs/GUIDE.md#12-хостинг-wispbyte).

Подойдёт и любой другой хостинг с Python 3.11+ и постоянным процессом:
склонировать репо, `pip install -r requirements.txt`, положить `.env`,
запускать `python bot_gelbooru.py`.

## Безопасность
Токены и ключи — только в `.env`/переменных хостинга, в git они не попадают.
Если токен утёк — Discord Developer Portal → Bot → Reset Token.

## Поиск по всей выдаче и строгий анти-повтор (v3.2–v3.3)
- Бот не ждёт индексирования сотен тысяч постов перед первым результатом.
- Порядок: strict (нагота) → фокус запрошенной части тела → score.
- Ранняя остановка с доказательством и исчерпание бюджета — разные состояния.
  Для запроса с фокусом части тела, если приоритет ещё не подтверждён,
  вместо менее подходящего арта выдаётся прогресс с Next. При подтверждённой ранней
  остановке скачивание ограничено доказанными кандидатами; ниже по приоритету
  не откатываемся при ошибках файлов. После полного обхода доступен обычный fallback.
- За вызов догружается до 6 страниц. Это НЕ общий предел: следующие запросы продолжают
  с курсора. Потолок Gelbooru в 20 000 постов обходится курсором `score:`/`id:`.
- Индекс и курсор в `DATA_DIR/search_cache` переживают рестарт и вытеснение из RAM.
  Одновременно держим до 4 открытых индексов. Незавершённый обход не сбрасывается через 10 минут.
- `count` API — подсказка, не доказательство доступности всех страниц. Пустая
  страница до count или повторяющаяся пагинация логируются отдельно.
- В запросах без фокусного приоритета уже проиндексированные НОВЫЕ посты
  доступны при таймауте/сбое поздней страницы (это лучший из просмотренных, не
  обещание глобального оптимума). Приоритетные запросы ждут подтверждения.
  Старые арты не возвращаются. 401/403/429 остаются явными ошибками.
- Поиск читает историю канала напрямую через read-only SQLite attachment,
  без копирования всей истории в Python и временную таблицу на каждый запрос.
  Проверка и резерв перед отправкой по-прежнему атомарны; историю не удаляем.
- Готовые обходы после 10 минут могут обновляться; частичный индекс не является
  актуальным полным снимком сайта. Для ручного переиндексирования можно удалить
  только `search_cache` при остановленном боте. Хеш контент-политики инвалидирует
  старые индексы после изменения фильтров.
- SQLite-история общая для одного Discord-канала, независимо от тегов и booru-сайта.
  В другом канале свой журнал. Старые записи не вытесняются; автоматические повторы запрещены.
- Проверяются ID поста, MD5 API и MD5/SHA256 реально скачанного файла.
  Это не распознавание похожих изображений: кроп/перекодировка другого поста могут отличаться.
- При неопределённой доставке резерв остаётся: лучше пропуск, чем возможный дубль.
- **DATA_DIR должен быть постоянным и доступным для записи. Не удаляй `shown.sqlite3`.**
- Старый `recent_shown.json` импортируется один раз с консервативным общим запретом.
  Уже забытые старым алгоритмом показы восстановить из файла невозможно.
- Контент-фильтры и NSFW-проверки сохранены. Для `/tg` глубина истории пока 200 сообщений.

Порядок обновления и ограничения: [docs/ANTIREPEAT.md](docs/ANTIREPEAT.md).

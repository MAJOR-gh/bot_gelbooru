# Gelbooru Discord Bot (v3.5.4)

Discord-бот на `nextcord`: ищет арты по тегам на booru-сайтах и в
Telegram-каналах и присылает картинки / GIF / видео. Показывает лучший по
лайкам арт, который в этом Discord-канале ещё не показывал. Ищет по **всей** выдаче
тега — в том числе глубже потолка пагинации Gelbooru (20 000 постов).

## Команды
- `/gelbooru <тег> [тег2] [тег3] [тег4]` — арт по 1–4 тегам с **Gelbooru**.
  Ищешь часть тела (breasts/ass/pussy/feet) — наверх идёт арт, где она и есть
  сюжет, а не фоновый тег. `-тег` исключает тег.
- `/konachan <тег> …` — то же с **Konachan** (аниме-арт).
- `/safebooru <тег> …` — **Safebooru**, только safe-контент; работает в любом канале.
- `/tg [канал]` — топовый по реакциям пост из **Telegram**-канала (реклама
  отсеивается), весь альбом целиком.
- `/tags` — популярные теги и сколько по ним артов.
- `/tagcheck <тег>` — есть ли тег на Gelbooru + похожие теги при опечатке.
- `/help` — справка.
- `/status` — приватная диагностика API, задержки Discord, кэша и последнего поиска в канале.

В приватной панели — **Next**: продолжает тот же запрос без повторов. Панель видит
только автор в исходном канале, действует 10 минут и использует кулдаун исходной команды.
После рестарта старые кнопки не работают — повтори команду (дисковый курсор сохранён).
Все четыре поля тегов поддерживают автодополнение и подсказки опечаток.
В обычных каналах — только безопасные локальные подсказки; в NSFW-каналах —
также API Gelbooru/Safebooru, если доступно. Для Konachan — локальные варианты.
Подсказка не заменяет введённый тег автоматически и не гарантирует его наличие на сайте.

NSFW-команды (`/gelbooru`, `/konachan`, `/tg`, `/tagcheck`) работают только в
NSFW-каналах.

`1boy` разрешён: наличие мужского персонажа само по себе не блокирует пост.
Яой/фембой-контент по-прежнему отсекается точечными тегами (`yaoi`, `bara`,
`male_focus`, `male_only`, `femboy`, `crossdressing`, `otoko_no_ko`, `otokonoko` и др.).
Обязательный `hetero` не добавляется, чтобы не терять solo-арты.
Фильтр зависит от разметки сайта и не гарантирует распознавание нетегированного контента.

## Переменные окружения
Кладутся в файл `.env` рядом с ботом (шаблон — `.env.example`) или в
переменные окружения хостинга.

- `DISCORD_BOT_TOKEN` — токен бота (**обязательно**).
- `GELBOORU_API_KEY` / `GELBOORU_USER_ID` — **обязательно для /gelbooru**: без
  ключа Gelbooru отвечает 401. Берутся на gelbooru.com → My Account → Options.
- `DISCORD_GUILD_IDS` — ID серверов через запятую для **мгновенной** регистрации
  команд. Пусто → глобальная регистрация (до ~1 ч).
- `TG_API_ID`, `TG_API_HASH`, `TG_SESSION_STRING` — для `/tg`. Строку сессии
  выдаёт `python tools/tg_export_session.py`. Без них `/tg` отключена.
- Необязательно: `GELBOORU_PROXY` (если сайты заблокированы), `MAX_UPLOAD_MB`
  (потолок размера файла), `DATA_DIR` (куда писать память показанного),
  `PORT` (если хостинг его задаёт — поднимается health-эндпоинт `/health`),
  `SEARCH_TIMEOUT_SECONDS` (бюджет поиска на вызов, по умолчанию 20 секунд, рабочий потолок 30).

## Запуск локально
```bash
python -m venv venv
venv\Scripts\activate            # Linux/macOS: source venv/bin/activate
pip install -r requirements.txt
copy .env.example .env           # и впиши токен/ключи
python bot_gelbooru.py
```

## Хостинг 24/7
Сейчас бот живёт на [Wispbyte](https://wispbyte.com/client) (бесплатно).
Обновление: push в `main` → **Restart** в панели — при старте сервер сам
скачивает свежий код и ставит зависимости. Подробно — в
[гайде, раздел 12](docs/GUIDE.md#12-хостинг-wispbyte).

Подойдёт и любой другой хостинг с Python 3.11+ и постоянным процессом:
склонировать репо, `pip install -r requirements.txt`, положить `.env`,
запускать `python bot_gelbooru.py`.

## Безопасность
Токены и ключи — только в `.env`/переменных хостинга, в git они не попадают.
Если токен утёк — Discord Developer Portal → Bot → Reset Token.

## Данные
- `DATA_DIR/shown.sqlite3` — история показов по Discord-каналам. **Хранить на
  постоянном диске, не удалять**: без неё бот начнёт повторяться.
- `DATA_DIR/search_cache/` — индексы и курсоры обхода выдачи. Одноразовые: можно
  удалить при остановленном боте, поиск просто начнётся заново. Неделю не
  тронутые индексы удаляются сами; правка `content_filter.py` создаёт новые.


### Персональная панель и визуальные повторы (v3.5)
Результаты booru публикуются в канале без кнопок. Автор получает приватную
панель Next / Завершить; после Next приходит новая приватная панель внизу,
а старая удаляется. Промежуточные сообщения поиска не накапливаются.
Срок действия — 10 минут. После рестарта или истечения срока повтори команду.
История общая для канала, включая запросы разных пользователей.

Для статических изображений сохраняется визуальный отпечаток: небольшое
изменение размера и JPEG-компрессии больше не делает изображение новым.
Сравнение консервативное: сильно обрезанные изображения, надписи, анимации,
видео и изображения больше 20 мегапикселей могут не распознаться.
Старые записи истории сохраняются, но визуальная история копится только
с новых показов. Новая зависимость Pillow устанавливается из requirements.txt.

Обычные теги запроса и исключения проверяются по метаданным перед отправкой.
Поддерживаемые алиасы нормализуются перед поиском; метатеги обрабатывает сайт.
Это не распознавание содержимого: ошибочная разметка сайта всё ещё возможна.


### Диагностика повторов
В `/status` поле «История повторов» содержит ID базы, число сохранённых
идентификаторов и визуальных отпечатков для текущего канала. Сравни ID до и
после рестарта: при смене используется другая база или прежняя была удалена.
Проверь постоянство DATA_DIR и сохранность shown.sqlite3 на хостинге.
Не удаляй историю для устранения повторов: это разрешит уже показанные файлы.
Горизонтальные зеркала распознаются с v3.5.2; обрезки могут пройти.

В v3.5.3 визуальный антидубль сравнивает также центральные обрезки на 2, 4 и 6 % с каждой стороны. Эти варианты сохраняются с новых показов.

В v3.5.4 после проверки SHA-256 файла бот сравнивает SHA-256 декодированных
RGBA-пикселей с учётом ориентации EXIF. Для уменьшенных, пересжатых и зеркальных
копий добавлен pHash с проверкой пропорций и цветов. Прежние визуальные отпечатки
остаются рабочими. Новые добавляются с новых показов, так как SQLite не хранит
сами изображения.

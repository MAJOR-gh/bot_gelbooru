# Гайд разработчика

Как устроен бот, где что лежит и как его менять, не сломав. Написано простым
языком: если ты знаешь Python на уровне «пишу функции и циклы», этого хватит.

---

## 1. В двух словах

Бот — это одна программа на Python, которая постоянно висит на связи с
Discord. Когда кто-то вводит `/gelbooru breasts`, Discord шлёт боту событие,
бот идёт на сайт с артами, выбирает лучший арт, который ещё не показывал,
скачивает его и отправляет в чат.

```
Discord ──/gelbooru──▶ проверки ──▶ поиск на сайте ──▶ фильтры ──▶ выбор лучшего
                                                                      │
   чат ◀── отправка ◀── скачивание файла ◀────────────────────────────┘
                 │
                 └──▶ запоминаем, что показали (чтобы не повторяться)
```

## 3. Путь одного запроса `/gelbooru` (по шагам)

Функция `run_booru_search` в `bot_gelbooru.py`. Ей всё равно, какой сайт —
сайт передаётся параметром (`GELBOORU`, `KONACHAN` или `SAFEBOORU`).

1. **Канал NSFW?** Если нет — «Пиздуй в NSFW канал!» (видит только автор).
   Для `/safebooru` эта проверка выключена.
2. **Чистим теги** (`clean_user_tags`): `Large Breasts` → `large_breasts`,
   пустые поля выкидываются, дубли тоже.
3. **Особые теги** (`tag_verdict`):
   - Kanzaki Hideri → отправляем картинку из `assets/`;
   - Venti → «судебное постановление»;
   - Felix/Astolfo → «предупреждение»;
   - запрещённый тег → «🚫 Один из тегов заблокирован.» (видит только автор,
     кулдаун не тратится).
4. **Кулдаун**: не больше 5 поисков за 30 секунд на человека.
5. **`defer()`** — говорим Discord «думаю…». У бота есть всего 3 секунды на
   первый ответ, а поиск дольше, поэтому сначала откладываем ответ.
6. **Поиск** — `search.search()` (подробно в разделе 6). Возвращает список
   кандидатов, лучшие первыми.
7. **Отправка** — `send_first_fitting()`: берём первого кандидата, качаем
   файл, шлём. Не скачался или слишком большой — берём следующего (до 8 попыток).
8. **Фиксируем отправку** (`memory.mark_sent`). Резерв был записан в SQLite ещё
   до скачивания; история проверена атомарно и по байтам, даже при параллельных запросах.

## 4. Фильтр контента (`content_filter.py`)

Каждый пост с сайта проходит через `post_is_allowed()`. Пост выкидывается, если:

| Слой | Что режет | Как сравнивается |
|---|---|---|
| Рейтинг | Для NSFW-команд — `general`/`safe`; для `/safebooru` — `questionable`/`explicit` | точно |
| `HARD_TAGS` | Яой, мужской контент (`1boy`!), фембои, фута, бондаж, БДСМ | точное совпадение тега |
| `HARD_SUBSTRINGS` | Вариации HARD: `yaoi_*`, `*_bondage`, `ball_gag`… | одно слово — как **слово** в теге (`futa` ловит `futa_on_female`, но НЕ `futaba_sakura`); фраза с `_` — как кусок текста |
| `CRITICAL_TAGS` | Возраст (`loli`, `child`, `young`…) | **кусок текста** где угодно в теге — самая жёсткая проверка, специально |
| `AI_SUBSTRINGS` | Нейроарт | кусок текста |
| `BLACKLIST_TAGS` | Всё остальное: фурри, жир, кровь, низкое качество и т.д. | точное совпадение тега |
| `DRESSED_TAGS` | `fully_clothed` и т.п. | точно |

Потом отдельно проверяется **нагота** (`has_nudity`): у поста должен быть хотя
бы один тег из `NUDITY_TAGS`. Посты без наготы не выкидываются, а уходят в
«запасные» (см. раздел 6).

### Как добавить запрещённый тег

- Обычный мусор (не нравится и всё) → допиши в `BLACKLIST_TAGS`.
- Тег, у которого много вариаций (`что-то_*`) и который надо резать жёстко →
  в `HARD_TAGS` (сам тег) и, если нужно, корень в `HARD_SUBSTRINGS`.
- **Осторожно с `HARD_SUBSTRINGS` и `CRITICAL_TAGS`**: короткое слово может
  зацепить нормальные теги. Перед коммитом проверь на сайте, что не отрежешь
  лишнее, и добавь тест (раздел 11).

`HARD_TAGS`, `CRITICAL_TAGS` и `AI_TAGS` ещё и отправляются на сайт в запросе
(`-loli -1boy …`), чтобы сайт сам их выкинул. `BLACKLIST_TAGS` в запрос не идёт —
он длинный, URL раздувается и Gelbooru отвечает ошибкой 413.

### Что юзер может искать

`tag_is_blocked()` решает, можно ли вообще искать тег. Запрещено: всё из
`BLOCKED_USER_TAGS`, точные теги из блэклиста и HARD, всё с возрастом/AI внутри.
Тег с минусом (`-futa`) разрешён всегда — он только **исключает**.

## 5. Фокус на части тела

Проблема была такая: ищешь `breasts`, а бот присылает арт, где главное —
задница, а грудь просто есть в кадре (тег `breasts` стоит на половине всего
NSFW). Решение — `FOCUS_GROUPS` в `content_filter.py`.

У каждой группы (`breasts`, `ass`, `pussy`, `feet`) три списка:

- `triggers` — теги юзера, которые включают группу (`boobs`, `large_breasts`…);
- `focus` — теги поста, которые значат «эта часть тела — главное в кадре»;
- `nudity` — какая нагота засчитывается именно для этой части.

Каждый пост получает **тир** (`focus_tier`):

| Тир | Значит |
|---|---|
| 3 | в фокусе то, что просили, и только оно |
| 2 | в фокусе то, что просили, но и другая часть тоже |
| 1 | нейтрально, явного фокуса нет |
| 0 | в фокусе **не то**, что просили |

Тир важнее лайков: тир 3 со score 50 покажется раньше тира 0 со score 5000.

Чтобы добавить новую группу (например `thighs`) — скопируй блок `"feet"` в
`FOCUS_GROUPS` и заполни три списка тегами с Gelbooru.

## 6. Как выбирается арт

### 6.1 Порядок выбора

1. Исключаем все известные каналу ID/MD5, резервы и временно недоступные файлы.
2. Среди новых — сначала strict, затем broad (запасные).
3. Внутри — по тиру фокуса и score. Бот читает выдачу дальше, пока не ДОКАЖЕТ, что лучше
   найденных кандидатов в непрочитанной части нет (см. 6.3), или пока не кончится бюджет вызова.
4. Если новых нет — сообщение об исчерпании, **не возврат старых артов**.

`selection.order_candidates` используется для списков (Telegram).
Для booru тот же порядок реализован ленивым SQL-запросом в `search_index.py` (`RANK_ORDER`).

### 6.2 История и резервирование

- Ключ = Discord guild/channel, не теги. История общая для всех пользователей канала.
- `shown.sqlite3` не имеет лимита в 500 записей или 500 запросов.
- SQLite WAL + `synchronous=FULL`: резерв записывается ДО внешней отправки.
- Сверяем идентификаторы поста и хеши реально загруженных байтов.
- Точно отвергнутая отправка освобождает резерв; неопределённая сохраняет его.
- Временные ошибки/слишком большие файлы исключаются на 5 минут, чтобы не
  застревать на одних и тех же верхних 8 кандидатах.
- Старый JSON импортируется один раз; подробнее в `ANTIREPEAT.md`.

### 6.3 Поиск по всей выдаче (`search.search`)

1. Сайт отдаёт выдачу по убыванию score. Страницы читаются по порядку (до 3 параллельно,
   до 6 за вызов) и складываются в дисковый индекс `search_cache` вместе с курсором.
2. **Доказанная остановка.** У непрочитанных постов score не выше последнего прочитанного
   (`frontier`). Если в индексе есть 5 непоказанных постов strict=1, с максимальным тиром
   фокуса и score ≥ frontier — лучше них во всей выдаче нет, читать дальше не нужно.
   Иначе бот читает следующие страницы. Раньше хватало «любых 5 новых», поэтому при запросе
   `breasts` бот мог отдать арт с фокусом на другой части тела, не дойдя до 2-й страницы.
3. **Потолок пагинации обходится.** Gelbooru не отдаёт страницы глубже 20 000 постов
   (`pid*limit`, ответ «Too deep»). Дойдя до потолка, бот переключается на курсор:
   все посты с `score:N` (N — frontier) листаются по `id:<…` (`sort:id:desc`), затем
   продолжается `score:<N sort:score` с первой страницы. Так доступна вся выдача
   тега — хоть 5 тысяч, хоть 500 тысяч. Если сайт неожиданно ответит «Too deep» раньше,
   бот переключится на курсор сам.
4. При таймауте/сбое страницы в запросе без фокусного приоритета доступны уже найденные
   **новые** посты. Это лучшие из просмотренных, не глобальная гарантия. Для фокусного
   запроса бюджет 6 страниц/таймаут не считается доказательством: `priority_pending`
   возвращает прогресс + Next. После доказанной остановки `restrict_to_proven` не даёт
   при ошибках скачивания откатиться к худшему недоказанному тиру. После полного обхода
   применяется обычное ранжирование. Проблемная страница не пропускается.
5. Если новых пока нет, бот сообщает прогресс. Следующий запрос продолжит с курсора,
   даже после рестарта. Частичный курсор не истекает; законченный обход перечитывается
   не чаще раза в 10 минут. Индексы, не тронутые неделю, удаляются сами.
6. `count` — ориентир. Читаем до пустой страницы; повтор страницы попадает в лог.
7. Konachan курсор не поддерживает (анонимам — не больше 6 тегов в запросе), но и
   потолка pid у него нет.
8. Safebooru временно отвечает HTTP 404 при всплеске запросов — это считается лимитом
   (`rate`) с повтором, а не «сломанной выдачей».

`SEARCH_TIMEOUT_SECONDS` = 20 по умолчанию, рабочее значение ограничено 30 секундами.
`exhaustive=True` — прочитать всё (тесты/диагностика), команды Discord его не используют.

### v3.4: история без полного копирования

`ShownMemory.search_history(scope)` возвращает `HistoryView` для дисковой БД.
Индекс подключает её через SQLite URI `mode=ro`, проверяет sent/pending/blocked,
legacy-историю и временный карантин через индексированные `NOT EXISTS`.
История других каналов не исключается. Для `:memory:` сохранён set-fallback.
Последняя защита доставки — прежняя атомарная `reserve`/`extend`; SQL-проверка
не заменяет её при конкурентных запросах.

### v3.4: интерфейс и диагностика

- `search_ui.NextView`: срок 600 с, author/channel checks, lock двойного клика.
  Сохраняет теги/источник/cooldown, запускает общий `run_booru_search`.
  Persistent views не используются; после рестарта нужен новый вызов команды.
- `tag_help`: normalizer, fuzzy local fallback, safe-only вне NSFW, API budget 1 с,
  не больше 25 choices, кэш до 128 ключей на 10 минут. Konachan — локально.
- `diagnostics`: `/status` ephemeral; probe каждого API до 5 с, кэш 60 с,
  исключения отображаются как безопасный код состояния, без сырых URL/параметров.
  Метрики последнего поиска — до 128 каналов в памяти, без текстов запросов.

## 7. Скачивание и отправка

- Для каждого поста пробуем по очереди: оригинал → `jpeg_url` (Konachan) →
  `sample_url` (сжатая версия). Если оригинал больше лимита — берём сжатую,
  в embed будет пометка «сжатая».
- **Лимит Discord**: 10 МБ, на серверах с бустом 2+ уровня — 50/100 МБ
  (`max_upload_size`). Минус полмегабайта запаса.
- Gelbooru без заголовка `Referer` отдаёт вместо картинки HTML-страницу. Поэтому
  каждый сайт шлёт свой `Referer`, а `download()` проверяет, что пришёл не текст.
- Если Discord ответил 413 («слишком большой») — пробуем следующего кандидата.
- Перед отправкой SQLite атомарно резервирует ID и хеши в области канала.
  Это защищает и разные теги, и устаревшие списки кандидатов параллельных запросов.
- Бюджет скачивания/отправки — 180 секунд, до 8 попыток файлов за вызов.
  Это ограничение времени, а не глубины поиска; ошибочные файлы временно пропускаются.

## 8. Telegram (`/tg`)

Бот читает каналы как обычный пользователь Telegram (userbot через Telethon).

- Нужны `TG_API_ID`, `TG_API_HASH` (my.telegram.org → API development tools) и
  `TG_SESSION_STRING` — «ключ входа» аккаунта.
- Получить `TG_SESSION_STRING`: локально `python tools/tg_login.py` (вход по номеру
  телефона, создаёт `tg_userbot.session`), потом `python tools/tg_export_session.py` —
  он напечатает строку. Эту строку — в `.env` на хостинге. **Это доступ к
  аккаунту Telegram, никому не показывай.**
- Каналы — в `tg_channels.json`: `{"alias": "имя_для_команды", "peer": id}`.
  ID приватного канала узнать: `python tools/tg_list_channels.py`.
- Бот смотрит последние 200 сообщений канала, склеивает альбомы в один пост,
  выкидывает рекламу (кнопки, рекламные слова — список `AD_KEYWORDS`) и
  показывает самый залайканный (по реакциям) из ещё не показанных.
- Скан канала кэшируется на 10 минут.

## 9. Слэш-команды Discord

- Команды регистрирует сама библиотека nextcord при подключении.
- `DISCORD_GUILD_IDS` задан → команды появляются на этих серверах **сразу**.
  Пусто → глобально, Discord обновляет до часа.
- Если команды двоятся — значит висят и глобальные, и серверные. Бот сам
  сносит лишние при старте; если не помогло — перезапусти бота.

### Как добавить команду

```python
@bot.slash_command(name="ping", description="Проверка, жив ли бот")
async def ping(interaction: nextcord.Interaction):
    await interaction.response.send_message("🏓 Понг!", ephemeral=True)
```

`ephemeral=True` — ответ видит только тот, кто вызвал. Если команда думает
дольше 3 секунд — сначала `await interaction.response.defer()`, а потом
`await interaction.followup.send(...)`.

Новый booru-сайт: сделай класс в `sources.py` по образцу `Safebooru` (движок Gelbooru —
наследуй `DapiSource`; иначе методы `request`, `normalize`, `post_url`), создай объект в
`bot_gelbooru.py` и команду через `register_booru_command`
по образцу `/konachan`.

```bash

```

**Тесты** — запускай после каждой правки:


```python
check("cat_ears не блокируется", cf.tag_is_blocked("cat_ears") is False)
```

## 12. Хостинг (Wispbyte)

Бот живёт на [wispbyte.com](https://wispbyte.com/client), сервер `gelbooru-bot`.

- **Команда запуска** (Configuration → Startup) при каждом старте: скачивает
  свежий код с GitHub (`main`), ставит зависимости, запускает бота.
- **Обновить бота** = запушить в `main` на GitHub → в панели нажать
  **Restart**. Всё.
- **Секреты** — файл `.env` в Files (корень сервера). Git его не трогает.
- **Логи** — вкладка Console. Там видно ошибки.
- **Запуск** на бесплатном тарифе — через рекламный ролик (жмёшь Start, ждёшь
  ролик). Если блокировщик рекламы мешает — выключи его для wispbyte.com.
- **Раз в 2 недели заходи в панель** — иначе сервер выключат как неактивный.
- Если бот лёг сам — Console → Start. Если хостинг совсем умер — бот запустится
  на любом другом хостинге с Python: `git clone`, `.env`,
  `pip install -r requirements.txt`, `python bot_gelbooru.py`.

## 13. Частые проблемы

| Симптом | Причина | Что делать |
|---|---|---|
| «Gelbooru отказал в доступе» | нет/неверный API-ключ Gelbooru | проверь `GELBOORU_API_KEY`/`USER_ID` в `.env` |
| «Gelbooru ограничил частоту» | слишком много запросов | подождать минуту |
| Команды не появились | глобальная регистрация идёт до часа | впиши `DISCORD_GUILD_IDS` и перезапусти |
| Команды двоятся | висят глобальные и серверные | перезапусти бота |
| `/tg` пишет «не настроен» | нет `TG_*` в `.env` или сессия протухла | раздел 8, в логе при старте строка `[tg] env:` |
| В логе `Websocket closed with 4004` | неверный токен Discord | новый токен в `.env` |
| «Приложение не отвечает» в Discord | бот офлайн | Console → Start, смотри логи |
| Тег точно есть на сайте, а бот «ничего не найдено» | все арты срезал фильтр (часто — `1boy` из HARD) | проверь пару постов на сайте: какие теги из `content_filter.py` на них стоят |

# Анти-повтор

## История показов

`DATA_DIR/shown.sqlite3` — журнал в области **Discord-канала**: люди, запросы,
исключающие теги и booru-сайты одного канала делят его. Другой канал (и ветка)
независим. Записи не вытесняются — лимита в N показов нет.

Проверяются ID поста, MD5 из API и MD5/SHA256 реально скачанного файла. Это не
perceptual hash: кроп или перекодировка того же арта под другим постом могут не
распознаться. Telegram-альбом проверяется по ID альбома и по байтам каждого
вложения; совпало любое вложение — пропускается весь пост.

## Резерв перед отправкой

Резерв пишется в SQLite (WAL, `synchronous=FULL`) **до** скачивания, подтверждённая
отправка фиксируется отдельной короткой транзакцией.

- Точно отвергнутая отправка (например 413) освобождает резерв.
- Если отправка началась, но подтверждение потерялось (сеть/5xx/отмена/крах),
  резерв **не снимается**: возможен пропуск недоставленного арта, зато не будет
  дубля. Автоматического «сброса ради нового арта» нет.
- Битые и слишком большие файлы исключаются на 5 минут, до 8 попыток и 180 секунд
  на скачивание/отправку за вызов. Глубину поиска это не ограничивает.

## Старая история

При первом запуске один раз импортируется `recent_shown.json` из DATA_DIR. Каналов в
нём нет, поэтому его ID блокируются во **всех** каналах. Маркер импорта хранится в
SQLite, JSON не перезаписывается. Повреждённая история останавливает запуск, а не
обнуляет защиту.

## Чего нельзя

- Удалять `shown.sqlite3` (вместе с `-wal`/`-shm`) — защита от повторов пропадёт.
- Копировать живую базу на ходу: только при остановленном боте.
- Класть историю в git или Docker-образ. DATA_DIR должен быть постоянным и
  доступным для записи (в Docker — volume).

`search_cache/` удалять можно (при остановленном боте): это одноразовые индексы
выдачи, история показов в них не хранится.
